# Decision Record NNNN — Short Title

| Field | Value |
| --- | --- |
| Status | Proposed / Accepted / Superseded / Rejected |
| Date | YYYY-MM-DD |
| Scope | Repository-wide / bounded scope |
| Owner Review | Required / Not required / Pending |

## Decision

State the decision in concise, implementation-neutral terms.

## Context

Explain the problem, constraints, and why a decision is needed.

## Authoritative Sources

List the controlling Book I, Book II, Book III, Book IV, Book X, and accepted-record references. State explicitly that higher-order sources prevail.

## Alternatives Considered

List material alternatives and why each was not selected.

## Consequences

Describe intended benefits, constraints, risks, compatibility effects, and reversal or supersession conditions.

## Implementation Implications

State what implementation work is enabled, constrained, deferred, or prohibited. Do not turn the record into an implementation specification.

## Owner Review Assessment

State whether Owner Review is required and why. If required, record the decision request using the escalation structure in `agents.md`; do not mark the decision accepted without the required authority.

## Continuity Notes

Record follow-up documentation, conformance, migration, or review work needed for a future session.
